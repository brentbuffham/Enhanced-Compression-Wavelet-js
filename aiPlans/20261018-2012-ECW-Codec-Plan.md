# ECW Codec Implementation Plan (Plan 2 of 3)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Locate and frame every block in an ECW file (tested), then crack the two stream coding modes and the coarsest-level reconstruction until our level-0 pixels match GDAL.

**Architecture:** `EcwBlockIndex` turns the index header into a block grid and byte ranges; `EcwBlockFrame` splits a block into mode-tagged streams. Both are pure, over the Plan 1 source contract. The codec (stream decode → dequantise → inverse wavelet → colour) is research first: probes in `_dev/ecw-decode/`, facts promoted to `src/codec/` only through failing tests. Plan 3 (written at the end of this plan) covers `readRegion`, `BlockCache`, the Worker and the demo.

**Tech Stack:** Vanilla JS ES modules, `node --test`, QGIS 4.2.3 GDAL references in `samples/ref/`.

**Spec:** `docs/superpowers/specs/2026-10-18-ecw-decoder-design.md` (§7 now holds the block index and framing layout). Evidence: `_dev/ecw-decode/FINDINGS.md`.

## Global Constraints

Plan 1's Global Constraints apply unchanged (zero deps, `node --test "test/**/*.test.js"`, test-first, `var`/tabs/banners/JSDoc, 64-bit by multiplication, no private data in git, commit per task to `main`).

## Review Focus

1. **Huge indexes** — the block index can be hundreds of MB on large files; never read it whole. Entry reads are 16-byte windows. Pinned in Task 1.
2. **Corrupt index** (falling offsets, an end marker that misses the file size, entry count that disagrees with the level grid) — `BAD_BLOCK_INDEX` with the offset. Pinned in Task 1.
3. **Edge blocks** (last column / row narrower than 64) — grid counts use `ceil`; framing must not assume full blocks. Pinned in Tasks 1–2.
4. **Corrupt block framing** (offsets beyond the block, falling offsets, empty block) — `BAD_BLOCK` with the block-relative offset. Pinned in Task 2.
5. **Single-band files** — stream counts are assumed `bands × 4` / `bands × 3`; only 3-band evidence exists. Flagged in FINDINGS; a 1-band sample would settle it.

### Task 1: EcwBlockIndex

**Files:**
- Create: `src/format/EcwBlockIndex.js`, `test/helpers/buildEcwFile.js`
- Modify: `src/errors.js` (add `BAD_BLOCK_INDEX`, `BAD_BLOCK`), `test/errors.test.js` (code list), `src/index.js` + `test/EcwReader.test.js` (export `parseBlockIndex`, `blockGrid`)
- Test: `test/format/EcwBlockIndex.test.js`

**Interfaces:**
- Consumes: `parseHeader`, `parseLevels`, `levelTableEnd` (Plan 1).
- Produces:
  - `parseBlockIndex(source, header) → { indexOffset, bodyLength, flag, entryCount, offsetsStart, dataStart }` where `indexOffset = levelTableEnd(header)`, `bodyLength` = u32 BE at `indexOffset`, `flag` = u8 at `indexOffset + 4`, `offsetsStart = indexOffset + 5`, `entryCount = (bodyLength - 1) / 8`, `dataStart = indexOffset + 4 + bodyLength`. Needs only the first `indexOffset + 5` bytes. `(bodyLength - 1) % 8 !== 0` → `BAD_BLOCK_INDEX` at `indexOffset`.
  - `blockGrid(header, levels) → [{ level, cols, rows, firstBlock }]` with `cols = ceil(width / blockWidth)`, `rows = ceil(height / blockHeight)`, `firstBlock` cumulative from 0.
  - `totalBlocks(grid) → number`.
  - `blockNumber(grid, level, row, col) → number` (row-major within level); out of range → `INVALID_ARGUMENT`.
  - `blockEntryWindow(index, n) → { start, end }` = the 16 file bytes holding entries `n` and `n + 1`.
  - `blockByteRange(index, n, entryBytes: Uint8Array(16), fileSize) → { start, end }` = `dataStart + off[n]`, `dataStart + off[n+1]` (u64 LE via `readU64`). Falling → `BAD_BLOCK_INDEX` at the entry; end past `fileSize` → `TRUNCATED`.
  - `readU64` returns `null` past 2^53, and `null + n` silently becomes `n`: `blockByteRange` must throw `BAD_BLOCK_INDEX` on a null entry before any offset maths (final review R1).
  - `blockGrid` must reject `blockWidth` or `blockHeight` of 0 with `BAD_BLOCK_INDEX` at `0x12` / `0x14` (a zero would make `ceil` return Infinity; final review M2).
  - `checkBlockIndex(index, grid) → void`: `entryCount !== totalBlocks(grid) + 1` → `BAD_BLOCK_INDEX` at `indexOffset`.
  - Test helper `buildEcwFile({ headerOverrides, blocks: Uint8Array[] }) → Uint8Array`: header from `buildEcwHeader`, then `u32 BE bodyLength`, flag `1`, `blocks.length + 1` u64 LE relative offsets, then the block bytes.

- [ ] **Step 1: Write failing tests** — `parseBlockIndex` fields on a synthetic file with 3 levels (1000×600, 64-px blocks → grid cols/rows `2×2, 4×3, 8×5`, 4 + 12 + 40 = 56 blocks, `entryCount` 57); `blockGrid` `firstBlock` values `0, 4, 16`; `blockNumber(grid, 1, 2, 3) === 4 + 2*4 + 3`; `blockByteRange` returns each synthetic block's exact bytes; last block end equals file length; a 1-px-high edge row (height 65 at level 0 → rows 2); falling offset → `BAD_BLOCK_INDEX`; end past file → `TRUNCATED`; entry count mismatch → `BAD_BLOCK_INDEX`; `(bodyLength - 1) % 8` ≠ 0 → `BAD_BLOCK_INDEX`; offsets above 2^32 read exactly (craft one entry `0x1_0000_0010` with a fake `fileSize`).
- [ ] **Step 2: Run** `npm test` — Expected: FAIL (module missing).
- [ ] **Step 3: Implement** `src/format/EcwBlockIndex.js` and the error codes.
- [ ] **Step 4: Run** `npm test` — Expected: all pass.
- [ ] **Step 5: Commit** — `feat: ECW block index and block grid`

### Task 2: EcwBlockFrame

**Files:**
- Create: `src/format/EcwBlockFrame.js`
- Test: `test/format/EcwBlockFrame.test.js`

**Interfaces:**
- Produces:
  - `STREAM_MODE = Object.freeze({ EMPTY: 5, CODED_A: 2, CODED_B: 6 })`.
  - `streamCount(bands, level) → bands * 4` when `level === 0`, else `bands * 3`.
  - `splitBlockStreams(bytes: Uint8Array, bands, level) → [{ band, subband, mode, bytes }]`, band-major: level 0 subbands `["LL","LH","HL","HH"]`, others `["LH","HL","HH"]`. Header = `count - 1` u32 BE offsets relative to the header end; `bytes` excludes the mode byte. Errors (`BAD_BLOCK`, offset relative to block start): block shorter than header; offsets falling or past the block; a zero-length stream; unknown mode byte. A mode-5 stream must be exactly 1 byte, else `BAD_BLOCK`.

### Task 4: Research — stream modes 2 and 6

Research, not TDD. Deliverable: FINDINGS sections and a spec update precise enough to write a failing test for each decoder.

**Questions:**
1. What a mode-2 stream decodes to: count of values (64×64 per subband, or edge size), value range, sign handling.
2. Same for mode 6, and what distinguishes the two (block content, subband, band).
3. Whether a stream is self-delimiting (decoder consumes exactly its bytes) — the strongest check for a correct guess.

**Method:**
- Smallest cases first: 1-px edge blocks at level 0 and blocks whose coded streams are under ~30 bytes. Collect them with a probe `_dev/ecw-decode/smallStreams.mjs`.
- Tabulate byte and bit statistics after the mode byte (`byteStats.mjs`, a new bit-histogram helper in `probeLib.mjs` with tests).
- Test candidate coders against the self-delimiting check: run-length + Huffman (table in stream?), Rice/Golomb, adaptive binary arithmetic. Record every ruled-out candidate under "Ruled out (don't re-walk)".
- Cross-check against pixels: level 0 `LL` streams should correlate with `samples/ref/level-0.tif` once decoded.

**Done when:** a probe decodes every mode-2 and mode-6 stream in 2,000 sampled blocks, consuming each stream's bytes exactly, and FINDINGS documents both formats.

- [ ] **Step 1–4:** probes and FINDINGS as above. **Step 5: Commit** — `docs: stream coding findings`
